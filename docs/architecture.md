# Архитектура фронтенда

Проект использует Feature-Sliced Design. Официальный skill установлен локально:
`.agents/skills/feature-sliced-design/SKILL.md`.

## Слои

- `src/app` — маршрутизация Next.js App Router, layout, оболочка, провайдеры и глобальные стили.
- `src/_pages` — композиции экранов: dashboard, workspace, modules, rations.
- `src/features` — пользовательские действия и формы.
- `src/entities` — доменные модели и расчёты.
- `src/shared` — HTTP-клиент, базовые UI-компоненты и оформление.
- `backend` — отдельная серверная архитектура: HTTP → application → domain/infrastructure. FSD не переносится механически на backend.

`_pages` — слой Pages с именем, безопасным для Next.js. Существующий `src/app`
оставлен на месте вместе с `src/proxy.ts`, чтобы сохранить маршрутизацию.
Это локальное отличие от примера skill с корневым `app` и `src/_app`.

## Импорты

Направление зависимостей: `app → _pages → features → entities → shared`.
Внешние потребители слайсов используют только `index.ts`, например
`@/entities/ration`. Внутренние импорты слайса относительные.
Публичные экспорты перечисляются явно; общих index для целых слоёв нет.
UI с `use client` сохраняет директиву в исходном модуле. Серверные модули
не экспортируются вместе с клиентскими компонентами.

Связи `pet → breed/customer`, `standard → pet/breed`, `module → breed`
сохранены через узкие типовые API `@x/<consumer>`. Питомец содержит породу
и владельца, норматив содержит пол и вид, модуль содержит вид животного.
Эти контексты имеют собственные формы и жизненные циклы, поэтому слияние
в одну сущность ухудшило бы границы. Через `@x` экспортируются только нужные типы.

Справочная вкладка входит в dashboard: её UI локален этому слайсу.
Общие компоненты таблиц и панелей остаются в Shared. Существующие формы
в Features сохранены; новые одноразовые формы следует размещать рядом с экраном.

## Проверка

`npm run lint` проверяет направление импортов, изоляцию слайсов и публичные API,
включая относительные пути и динамические импорты с литералами.
`npx tsc --noEmit` проверяет контракты, `npm run build` — интеграцию с Next.js.
Правило находится в `tooling/eslint/fsd.mjs` и не требует отдельного пакета.

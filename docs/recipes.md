# Рецепты

## Импорт плова

Миграция `20261120120000_vetdietolog_pilaf_recipe` добавляет один общий рецепт
[«Плов» для взрослых собак](https://vetdietolog.ru/recipes/dogs/dog-pilaf).
Источник проверен 20 ноября 2026 года. Royal Canin и другие примеры не добавляются.

Используется существующий `Product` с типом `RECIPE`, владельцем
`bootstrap-admin` и `isShared = true`. КБЖУ хранятся в полях продукта;
сырая клетчатка (`CFi`), зола (`CAs`) и влага (`MO`) — в `ProductNutrient`.
Импорт учитывает единицы существующего справочника. Неопубликованные нутриенты
не создаются и не подменяются подтверждёнными нулями.

Поля `recipeInstructions` и `recipeNotes` сохраняют порядок приготовления
и условия применения. Они необязательны и не меняют существующие продукты.
Основа в 100 г означает единицу пищевой ценности, а не выход готовой партии.
Расчётных ингредиентов, дозировки добавки и предполагаемой массы блюда нет.

Повторный запуск не перезаписывает рецепт, его ручные изменения, архивное
состояние или мягкое удаление. Записи с тем же источником также не дублируются.
Нет изменений пользователей, их паролей, продуктов, расчётов и рационов.
Старые миграции не редактируются. Отсутствие необходимых справочных нутриентов
вызывает явную ошибку с откатом новой миграции вместо неполного импорта.

## Редактор и реестр

Реализовано локально 20 ноября 2026 года. `/recipes` — отфильтрованный реестр
общего каталога Product, не отдельный дублирующий справочник. Доступны создание
в модалке (на мобильном во весь экран), редактирование и мягкое удаление.
Карточки всех типов имеют адрес `/products/:id`, печать — `/recipes/:id/print`.

Единая фича `features/edit-product` меняет форму по типу:

- Продукт/добавка: ручной состав на указанную базовую массу.
- Рецепт: **продукты и добавки**, граммовки, выход блюда, состав на 100 г,
  приготовление и примечания. Вложенные рецепты запрещены и в UI, и на сервере.
- Можно ввести КБЖУ/нутриенты вручную без ингредиентов либо скорректировать расчёт.
- Начальный выход при добавлении ингредиентов — сумма масс. Явно заданный выход
  автоматически не заменяется; массу после приготовления можно указать отдельно.
- Расчёт: сумма `состав ингредиента × масса / базовая масса × 100 / выход блюда`.
  Базовая масса источника должна быть в г/мг/мкг/кг; единицы нутриентов сохраняются.
  Отсутствующий нутриент даёт `null`, а не подтверждённый ноль. Старые определения
  с разными ID, но одинаковыми кодом и единицей, объединяются.
- Изменение граммовок/выхода требует пересчёта до Save. Перезапись ручных значений
  требует подтверждения. Отмена подтверждения ничего не пересчитывает;
  «Отменить изменения» возвращает сохранённую форму.
- «Сбросить» берёт актуальные источники. Без ингредиентов все значения становятся
  нулевыми, включая вручную добавленные нутриенты.
- Удалённый, архивный, недоступный или ставший рецептом источник блокирует
  **весь** пересчёт. Старые значения остаются до замены/удаления ингредиента.
- Изменения каталога не пересчитывают уже сохранённые рецепты или рационы.
- Поиск по имени/коду нутриента есть в карточке и форме создания.
- Ингредиенты, тексты, питание, меры и теги сохраняются **одной кнопкой**,
  без промежуточного автосохранения.

Рецепт → продукт/добавка: подтверждение, очистка ингредиентов/приготовления и
обнуление питания в черновике; затем можно ввести новый состав до Save.
Продукт ↔ добавка сохраняет значения. Продукт/добавка → рецепт сохраняет состав,
приведённый к 100 г. Печать содержит массы, выход, приготовление, примечания
и КБЖУ без полного списка нутриентов; печатается **сохранённая** версия.

## Доступ и версии

Личные записи принадлежат пользователю-диетологу, не клиенту-владельцу питомца.
Админ видит все; созданные администратором записи общие. Пользователь видит
общие и свои, изменяет только свои. История — владельцу личной записи и админу,
но не читателям общего каталога. Общий рецепт содержит только общие источники;
админ, редактируя личный рецепт, выбирает источники, доступные его владельцу.

Новая миграция `20261121090000_product_versions_recipes` добавляет:

- Product.recipeIngredients (JSON снимки), recipeYieldGrams и revision;
- ProductVersion: полный снимок, автор, действие, `bus_begin`/`bus_end`;
- исходную версию каждой существующей записи, включая мягко удалённые;
- уникальность текущей версии и триггер защиты истории PostgreSQL.

Product — текущая проекция; ингредиенты хранятся вместе с её составом, а не
отдельной таблицей строк. Сервер проверяет ID и сам собирает снимки источников.
Это периоды сохранённых состояний, не возможность задним числом менять даты.
Транзакционный Save закрывает текущий интервал и создаёт следующую версию.
Старый снимок нельзя изменить/удалить; разрешено лишь один раз закрыть период.
Восстановление создаёт новую текущую версию, не переписывает прошлое.
Меры/нутриенты/теги восстанавливаются через историю целого продукта, не поштучно
из архива. При изменённых единицах нутриентов или недоступных справочниках
небезопасное восстановление блокируется.

`expectedRevision` и блокировки продукта/источников защищают конкурентные Save.
Изменение источника после предпросмотра требует повторного пересчёта.
RationItem.productSnapshot не меняется при редактировании, удалении или
восстановлении источника. Миграция не очищает базу и не меняет старые миграции.
Применяется штатным `npm run db:deploy`; учтённые миграции повторно не запускаются.

## API

- `POST /api/products`, `PATCH /api/products/:id`: целая форма; PATCH требует
  expectedRevision. GET возвращает форму и права.
- `POST /api/products/recipe-preview`: пересчёт без сохранения.
- `GET /api/products/:id/versions?page=0`: по 30 кратких версий;
  `?versionId=...`: отдельный полный снимок.
- `POST /api/products/:id/versions`: восстановление с expectedRevision.
- `DELETE /api/workspace/products/:id`: мягкое удаление с версией и аудитом.
- Старые изменяющие endpoints нутриентов/мер возвращают 409 с просьбой обновить
  страницу: открытая старая форма не может обойти атомарное сохранение.

## Проверка

`npm run test:recipe-migration` проверяет импорт плова и новую историю версий.
Для проверки SQL на PostgreSQL требуется `TEST_DATABASE_URL` пустой локальной
базы с именем, заканчивающимся на `_test`. Тест никогда не очищает существующую базу.

`npm run test:recipes` проверяет чистые расчёты. При запущенном локальном приложении
`RUN_RECIPES_INTEGRATION=1 npm run test:recipes` также проверяет права, атомарность,
конкурентные Save, восстановление, смену типов, снимки рационов, клетчатку и
исключение удалённых строк из настоящего XLSX. Тестовые записи мягко удаляются.
Адреса: RECIPES_TEST_DATABASE_URL и RECIPES_TEST_URL; по умолчанию локальные
PostgreSQL :5434 и сайт :3000.

В браузере проверены вложенное создание ингредиента, ручная корректировка,
сброс, Save, восстановление версии, печать и полноэкранная модалка 390 px.

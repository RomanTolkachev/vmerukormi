# Таблицы, выбор записей и модальные формы

## Источник

Перенесён текущий `assets/inertia/Shared/universal-table` из локального mvdCake
(базовый commit `116d525be81175ca0fa8af55eafcc37567d63430`) вместе с используемыми
компонентами `Modal`, `modalStack`, `AsyncSelect`, `SelectInput`, floating portals,
кнопками, иконками и токенами. Это исходная реализация, не облегчённый аналог.
Внутренние файлы находятся в `src/shared/ui/kit`. API подключения приложения —
`src/shared/ui/universal-table/index.ts`.

Сохранены поиск, сортировка, пагинация, выбор строк, карточный режим, компактность,
порядок/видимость/ширина/закрепление колонок, разделение настроек списка и фильтров.
`LocalRegistry` подключает тот же компонент к уже загруженным данным.
Редактор состава рациона не заменяется реестром.

Выбор строк (`rowSelection`) включается только для конкретных действий над выбранными
записями. В текущих реестрах таких действий нет: чекбоксы выбора и счётчик выбранных
строк отключены. Чекбоксы включения продуктов в состав рациона остаются отдельной
функцией и не относятся к выбору строк таблицы.

## Адаптации

- Настройки сохраняются через существующий `/api/table-options/[tableName]`
  отдельно для каждого пользователя. Старый формат order/visible читается автоматически.
- Запись использует CSRF-клиент проекта. Очередь сохранения не затирает независимые
  изменения фильтров/колонок. Номер страницы и быстрый поиск не сохраняются.
- Next.js CSS Modules, серверный рендеринг и React 19 потребовали адаптаций
  селекторов и хуков; серверный snapshot modalStack стабилен.
- Тема приложения светлая, UUP; инфраструктура темизации всего mvdCake не переносилась.
- Формы при ширине до 767 px занимают весь экран и прокручиваются внутри окна.
  Escape закрывает только верхнее окно; Escape открытого селекта сначала закрывает список.
- Фокус ограничен верхним окном, нижние окна неактивны, прокрутка фона заблокирована.
- Заголовки и ячейки закреплённых колонок используют одно правило позиционирования.
  При ширине до 600 px закрепление отключается, чтобы действия не перекрывали данные;
  горизонтальная прокрутка заголовков и строк остаётся синхронной.
- Действия строки используют `tableActions`: кнопки и их подписи не переносятся
  и не сжимаются. Для нескольких действий задаётся `actionCellWidth`, достаточный
  для всех подписей, промежутков и отступов ячейки; узкий экран прокручивает таблицу,
  а не складывает кнопки в несколько рядов. Общий `actions` предназначен для форм.

## Единое оформление

Публичный API `shared/ui/controls` содержит `Button`, `ButtonLink`, `AnchorButton`,
`Input`, `Select`, `Textarea`. Они сохраняют нативные свойства и `ref`; состояние,
загрузка данных и валидация остаются в вызывающей форме. Компоненты таблицы и
асинхронного выбора используют перенесённый kit внутри Shared, без копирования
его реализаций в страницы. Линтер запрещает нативные элементы управления вне Shared.

Обязательный селект показывает `RequiredMark` рядом с подписью, в том числе после
выбора значения. `AsyncSelect` передаёт `aria-required`, нативный `Select` — `required`.
Постоянная подсказка «Обязательное поле» не выводится; ошибки остаются частью формы.

Все кнопки, включая ссылки-кнопки, иконки, очистку и закрытие модалок, используют
`shared/ui/button-motion`: подъём на 2 px при наведении мышью. Обычный `transform`
не заменяется, поэтому центрирование иконок сохраняется. Disabled/aria-disabled,
сенсорный ввод и `prefers-reduced-motion` не запускают подъём. `howerEffect` больше
не требуется. Базовый сброс шрифта имеет нулевую специфичность и не перебивает
типографику общих кнопок.

Библиотечные уведомления Sonner подключаются только через публичный API
`shared/ui/notifications`: `AppToaster` и `notify`. Провайдер приложения лишь
монтирует общий компонент. Цвета состояний, Golos Text, радиусы и кнопка закрытия
используют токены приложения; повторные сообщения сохраняют прежнюю дедупликацию
по id. Позиция — справа снизу, мобильные отступы — 16 px, доступные подписи — русские.

Палитра и адаптер токенов kit находятся в `src/shared/ui/styles/tokens.css`,
общие состояния и компоновки — в `ui.module.css`. Глобальное подключение шрифта
Golos Text находится в App; файл и лицензия OFL размещены рядом в `styles/fonts`.
Шрифт получен из [официального репозитория Google Fonts](https://github.com/google/fonts/tree/main/ofl/golostext).

Дизайн-система описана в корневом `DESIGN.md`. Для последующих изменений установлен
проектный skill Impeccable 4.8.0 (`.agents/skills/impeccable`), официальный источник —
`pbakaus/impeccable`, ревизия `f5c80432f883a0ee437735305eafc2a9e1bdb7a0`.
Он дополняет FSD, а не меняет направление зависимостей или правила предметной области.

## Создание и выбор

В реестрах используется кнопка создания. Для связей — асинхронный селект и
кнопка создания под ним. Новая запись автоматически выбирается в исходном поле.
Родительская форма не очищается. Выход из изменённой формы требует подтверждения;
успешно созданная дочерняя запись не удаляется при отмене родительской формы.

В редакторе рациона кнопка «Добавить продукт» открывает `FormDialog`: асинхронный
выбор продукта, мера, количество и день для недельного рациона. Создание продукта
открывается поверх этой формы и сохраняет её значения. Подбор по дефициту также
открывает эту модалку с рейтингом продуктов; ошибки добавления остаются внутри неё.
Состав занимает всю ширину, боковой панели и нижнего блока параметров нет.
Кнопка «Параметры рациона» открывает ту же форму `features/edit-ration`, что используется
для создания рациона из реестров и связанных форм. Её черновик не меняет основной экран
до сохранения; отмена изменённой формы требует подтверждения. Состав при сохранении
параметров сохраняется, а при переходе на суточный режим дни позиций становятся первыми.
Ручная цель калорий имеет приоритет над нормой выбранного расчёта.
Шапка состава с кнопками «Нутриенты» и «Добавить продукт» закрепляется при прокрутке
списка. Нутриенты открываются в общем `Modal`, на телефоне — на весь экран;
сохраняются все показатели, нормы и предупреждения о неполных данных.

Поддерживаются клиенты, питомцы, продукты, группы, теги, нутриенты, рационы,
методики и расчёты. События создаются из своего реестра; версии формул и меры
продукта — из модальных форм соответствующих карточек.
Породы являются справочником без создания; вид, пол и режим — перечисления.
Общие справочники и методики создаются только с соответствующими правами.

`/api/options/[entity]` возвращает до 30 результатов поиска и умеет загрузить
выбранную запись по `id`, даже если она не попала в первые результаты.
Фильтры учитывают владельца, питомца, вид животного и общий/личный каталог.
Права проверяются на сервере и при чтении, и при сохранении.

В таблицах питомцев связи не редактируются: клиент отображается текстом, а кнопка
«Карточка» открывает `/pets/[id]`. Назначение, смена и отвязка хозяина выполняются
там с явным сохранением. Создание клиента открывается во вложенной модалке;
изменение выбора само по себе не обновляет питомца.
В карточке редактируются имя, вид, пол, порода, фактический и идеальный вес, BCS
и заметка. Данные и хозяин сохраняются отдельными формами. Смена вида очищает породу;
сервер проверяет совместимость. Изменение веса пересчитывает BCS, после чего его
можно уточнить вручную. Отмена возвращает последние сохранённые значения.

## Проверка

- `npm run test:ui` — стек модалок, независимые настройки, закрепления и старый формат.
- `npm run test:pets` — черновики атрибутов, пересчёт BCS и независимое сохранение данных питомца.
- `npm run test:rations` — единый черновик общих параметров, зависимости выбора и сохранение без строк состава.
- `npm run test:catalog` — регрессии нутриентов и каталога.
- `npm run lint`, `npx tsc --noEmit`, `npm run build`.
- `tooling/catalog-smoke.mjs` — интеграционная проверка на отдельной локальной
  базе с `catalog_test` в имени: передать `DATABASE_URL` и `CATALOG_TEST_APP_URL`.
  Сервер должен использовать ту же тестовую базу. Рабочая база не допускается.

Для ручной проверки: создать продукт → создать группу → сохранить группу;
проверить автоподстановку и сохранность названия продукта, затем отменить продукт.
Повторить на мобильной ширине. Проверить сохранение ширины/закрепления колонок
после обновления страницы, фильтр по тегу и выбор записи вне первой выдачи.

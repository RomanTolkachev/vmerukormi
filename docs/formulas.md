# Формулы и единая форма расчёта

Согласовано 20 ноября 2026 года, включая коммит и публикацию на сервер.
Раздел «Справка» в этот выпуск не входит.

## Решения и приёмка

- Каталог закрытый. Ни админ, ни диетолог не создают и не редактируют выражения
  через UI/API. Старые версии остаются для истории.
- Выбор формулы меняет форму ввода. Поля определяет шаблон, а не диетолог.
  Показываются только используемые параметры и численные коэффициенты.
- Формулы беременности остаются; фазу выбирают вручную. Недели беременности
  нет ни в интерфейсе, ни среди параметров API, ни в новых колонках БД.
- Лактация требует неделю и число детёнышей для автоматических коэффициентов.
  K/L у кошки и N/M/L у собаки считаются по прежним правилам. Ручное значение
  заменяет автоматическое; пусто возвращает автоматику, 0 означает именно ноль.
  Если коэффициент задан вручную, его исходные параметры не обязательны.
- Пол не запрещает выбор формулы. Вид питомца ограничивает список;
  это повторно проверяется сервером.
- IW — идеальная масса; в формулах роста — ожидаемая взрослая масса. AW —
  фактическая масса. BCS не является входом текущих энергетических шаблонов.
- Все численные литералы, включая степени, можно менять без узких медицинских
  диапазонов. Операции и переменные фиксированы. Изменённые значения отмечены;
  сброс возвращает стандартные коэффициенты, автоматику и поправку ОЭ = 1.
- Изменения относятся только к текущему расчёту. Новый расчёт/выбор формулы
  начинает со стандартных коэффициентов; персональных пресетов нет.
- Отсутствующий обязательный параметр блокирует расчёт с названием поля.
  Формула никогда не сокращается и не подменяет пропуск нулём.
- Выражение находится под параметрами. После расчёта показаны использованные
  значения. КБЖУ и нутриентные нормы можно скорректировать перед сохранением.
- Под всеми числовыми полями есть пояснение смысла и роли в расчёте. Для
  автоматических K/L/N/M блок «Как рассчитывается» раскрывает правила текущего
  шаблона; правила L различаются для кошек и собак. Пусто/ручной ноль и
  стандартные коэффициенты объясняются отдельно. Подсказки не меняют математику.
- Сохранение находится слева рядом с расчётом, показывает общее уведомление.
  Имя обязательно при сохранении, уникально среди активных расчётов диетолога
  без учёта регистра и лишних пробелов. Удалённое имя можно использовать снова.
- Кнопки расчёта закреплены под прокручиваемыми параметрами, в том числе во
  вложенной модалке. Обе панели ограничены доступной высотой; на узком экране
  располагаются последовательно, без наложения длинных форм.
- В «Суточной норме» поиск по имени/коду нутриента всегда находится над
  прокручиваемыми значениями. Поиск не учитывает регистр, пробелы по краям и
  различие е/ё. Во время поиска показываются только совпавшие нутриенты;
  очистка запроса возвращает КБЖУ и весь список. Фильтрация не изменяет значения:
  сохранение отправляет все заданные нутриенты, включая скрытые поиском.

## Архитектура

Чистые шаблоны, поля, коэффициенты и проверки находятся в
`backend/domain/nutrition/parameters.ts`. Исходные выражения — в MODULES;
числовые литералы превращаются в C1/C2/… только для известных выражений,
не для введённого пользователем текста. Сервер принимает численные значения,
сверяет templateKey, moduleId, исходное выражение и применимые виды.

`features/calculate-energy` — общая форма для главного экрана, истории, клиента
и вложенного создания в рационе. Компоненты и модалки — Shared.
App-провайдер соединяет расчёт с механизмом создания через render-prop,
без перекрёстных импортов features.

Тексты и правила пояснений находятся в `features/calculate-energy/model/formula-help`.
`shared/ui/input-field` отвечает только за подпись, доступную связь подсказки
с полем и раскрытие подробностей; предметные правила в Shared не переносятся.

Module — существующая сущность формулы; ModuleFormulaVersion — версия.
Дополнительная параллельная таблица Formula не создаётся. Вид хранится в
расширяемом AnimalSpecies, применение — в speciesCodes версии и формулы.
Для новых видов нужны проверенные шаблоны через обновление приложения:
собачьи/кошачьи нормы не подставляются автоматически неизвестному виду.

## Миграция и сохранность

Добавочная миграция `20261122090000_formula_parameters`:

1. Создаёт справочник видов, массивы применимости и метаданные версий.
2. Добавляет имя, параметры, снимок формулы и bus_begin/bus_end расчёту;
   добавляет периоды рациону. Старые числа, связи и formulaVersionId не меняются.
3. Сохраняет прежнее выражение в снимке до открытия новых фиксированных версий.
   Старые версии закрываются, а не перезаписываются новым выражением.
4. Создаёт уникальный частичный индекс активного имени в пределах владельца.

Новый снимок содержит ключ версии шаблона, исходное выражение, структуру,
применённые коэффициенты, переменные и поправку энергии. Сохранённые результаты
не вычисляются заново при чтении. Менять реализацию v1 впоследствии нельзя:
другое правило требует нового ключа v2 и добавочной миграции.

Удаление расчёта закрывает bus_end и ставит deletedAt. Поиск новых связей его
не возвращает, но существующий рацион продолжает читать значения и выгружаться.
При редактировании такого рациона прежнюю удалённую связь можно сохранить;
привязать её к другому рациону нельзя. В селекте она помечена «удалён».
Восстановление открывает запись снова, если имя свободно. При занятом имени —
409; автоматических переименований нет.

Периоды Calculation/Ration обозначают активность записи, а не полную таблицу
снимков всех правок рациона. Удаление/восстановление остаётся в аудите.
История всех редакций состава рациона этим этапом не добавляется.

## Технические границы

Числа конечные; массы и поправка энергии положительные; неделя лактации —
целая положительная; число детёнышей — целое неотрицательное. Итог положительный,
энергия после округления помещается в PostgreSQL Int: 1–2 147 483 647.
Это ограничение хранения, не медицинский диапазон.

Отрицательные итоговые нормы/нутриенты, неизвестные параметры, выражения в
коэффициентах и устаревшая версия отклоняются. Изменение входов сбрасывает
предыдущий результат: его нельзя сохранить под новыми входами.

## Проверки и выпуск

- `npm run test:formulas` — 13 шаблонов против прежней математики, границы
  автоматики, пропуски, ручные коэффициенты, неизменность стандартных значений.
- `RUN_FORMULAS_INTEGRATION=1 npm run test:formulas` — локальные API, права,
  имена/конкурентное сохранение, снимки, удаление, восстановление и Excel.
- `TEST_DATABASE_URL=… npm run test:formulas:migration` — только новая пустая
  локальная БД с суффиксом _test; все предшествующие миграции и старый расчёт
  с отличающимся выражением.
- UI: главный расчёт; клиент → рацион → расчёт; реестр рационов → расчёт;
  переключение взрослый/беременность/лактация; возврат в родительскую форму;
  уведомление; полноэкранное окно на 390 px.
- `npm run lint`, `npx tsc --noEmit`, `npm run build`; регрессии продуктов,
  рецептов, рационов и экспорта.

При выпуске — migrate deploy и новая сборка приложения, без seed
и без изменения применённых миграций. Фактически опубликованный коммит
фиксируется на VPS в `/var/www/.vmerukormi-deployed-revision` после проверок.
«Полезное», лонгриды и SEO отложены.

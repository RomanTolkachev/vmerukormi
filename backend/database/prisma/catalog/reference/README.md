# Единицы и отображение как в Vetdietolog

Проверено в авторизованном интерфейсе `https://app.vetdietolog.ru/client/products`
31.10.2026. A, D, E — МЕ; B1–B6/C — мг; B7/B9/B12 — мкг;
минералы — мг, кроме Se/J (мкг); аминокислоты, включая Tau, и жирные кислоты — г.
Каротин остаётся отдельным обязательным показателем исходного Excel в мг.

Миграция `20261031090000_reference_nutrients` применяется после всех исторических
миграций и не изменяет их контрольные суммы. Интернет не нужен. Генератор:

```sh
node --import tsx backend/database/prisma/catalog/reference/generate.ts --check
```

Пересчитываются `ProductNutrient`, `CalculationNutrient`, `BreedStandardNutrient`.
Исходные алиасы остаются с `isReferenceOnly=true`: они не предлагаются при вводе,
не показываются отдельными карточками и не участвуют в суммировании. Записи
пользователей, продукты и рационы не удаляются и не публикуются. Определения
стандартных нутриентов bootstrap-каталога доступны всем пользователям.

## Не допускать двойного учёта

- Retinol переводится в A: 0,3 мкг ретинола = 1 МЕ. Если в продукте уже есть
  A, используется его значение, включая явный 0. `A_RE` не подменяет готовый
  витамин A: человеческие ретиноловые эквиваленты включают каротиноиды.
- D из мкг переводится в МЕ ×40; D3/D3_MCG заполняют только отсутствующий D.
  Суммарный D и его компонент D3 никогда не складываются.
- E переводится ×1,49 только при известном альфа-токофероле: health-diet,
  USDA SR Legacy или явно указанное в названии альфа-токоферольное значение.
  Для старого «E, мг» без подтверждённой формы нет универсального коэффициента.
  Оно сохраняется как скрытый `E_MG`; соответствующие нормы также сохраняются,
  но не пересчитываются наугад. В итоговом E будет 0/неполнота до уточнения
  состава. Нормализация не меняет исходные числовые факты на выдуманные.
- Известные нули сохраняются, `NULL` остаётся неизвестным значением.
- При совпадении канонической записи и алиаса применяется приоритет, не сумма.
  Индивидуальные нутриенты разных владельцев не объединяются между аккаунтами.
- Для неуказанных в образце нутриентов сохраняются исходные единицы и названия.

Коэффициенты проверены по [FEDIAF 2025, раздел 7.5, стр. 63](https://www.europeanpetfood.org/wp-content/uploads/2025/09/FEDIAF-Nutritional-Guidelines_2025.pdf).
Наличие одинаковой подписи в интерфейсе не доказывает одинаковую химическую форму.

## Рацион

Видны нутриенты с известным количеством (в том числе 0) хотя бы в одном
включённом продукте с положительным весом, плюс обязательные заголовки Excel.
Пустой рацион сохраняет обязательные показатели с 0 и пометкой отсутствия данных.
Нутриенты только из справочника или только из норм не добавляют лишние карточки.
КБЖУ берутся из основных полей продукта, как верхние виджеты. Остальные значения
считаются по базовому количеству продукта, в недельном режиме делятся на 7.
Excel использует тот же расчёт. Неполные данные не получают статус «в диапазоне».

## Проверки

`npm run test:catalog` проверяет суммы, обязательные поля и воспроизводимость SQL.
Интеграционный тест требует отдельную **пустую** локальную БД с окончанием `_test`:

```sh
TEST_DATABASE_URL=postgresql://postgres:postgres@localhost:5434/reference_catalog_test npm run test:reference-migration
```

Он накатывает исторические миграции, создаёт контрольные записи, применяет новую
миграцию и проверяет преобразования, отсутствие потери данных, нормы и права.
Не запускайте исторические генераторы импорта поверх нормализованной базы:
они оставлены для воспроизводимости старых миграций. Для расширения каталога
нужна новая миграция в действующих единицах, без повторного пересчёта старых строк.

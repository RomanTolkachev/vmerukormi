# Базовый каталог health-diet

Ниже описан первоначальный импорт и его исходные единицы. Следующая миграция `20261031090000_reference_nutrients` приводит данные к единицам сайта-образца и скрывает вспомогательные формы витаминов. Актуальные правила пересчёта и ограничения описаны в [reference/README.md](../reference/README.md). Старый генератор служит только для воспроизведения исторической миграции: новые импорты должны учитывать актуальные единицы, а не повторно добавлять исходные формы.

24 вручную отобранных базовых продукта, 1555 числовых значений, 139 определений нутриентов с учётом обязательных колонок калькулятора. Основной источник: `https://health-diet.ru/base_of_food/sostav/<id>.php`; URL каждой записи сохранён в `snapshot.json` и доступен из карточки продукта.

## Установка

`npm run db:deploy` применяет схему общего каталога и статическую SQL-миграцию `20261030091000_health_diet_catalog`. Интернет и запуск парсера для нового экземпляра приложения не нужны. Production Compose уже запускает сервис `migrate` перед приложением. `db:seed` для этого каталога не требуется.

Общие продукты видны всем авторизованным пользователям, включая созданных после миграции. Изменять их, состав, меры и теги может только ADMIN. Личные записи остаются личными; администратор не получает доступа к чужим личным записям. Общая запись может ссылаться только на общие группы, теги и нутриенты. Старые продукты USDA и пользовательские записи не публикуются и не перезаписываются.

В «Продуктах» общий поиск ищет по названию, группе и названиям тегов, отдельный фильтр выбирает точный тег. В рационе теговый фильтр не добавляется. Теги обозначают группу ингредиента и способ подготовки, не вид животного и не медицинскую пригодность.

## Отбор и точность

- `manifest.json` — закрытый список проверенных ID, названий, групп и способов подготовки. Самовольное переименование источника или новые страницы останавливают импорт. Добавление продукта требует ручного пересмотра списка.
- Мясо, птица, субпродукты, рыба, яйца, крупы, овощи, яблоко, масло и простые кисломолочные продукты; отдельно сырые и приготовленные варианты. Не импортируем пользовательские рецепты, бренды, алкоголь, колбасы, соусы, сладости, лук, чеснок, виноград и прочие исключённые ингредиенты. Автоматический запрет слов — дополнительная защита, а не полноценная ветеринарная экспертиза.
- Сырой ингредиент — запись состава для расчёта, а не рекомендация кормления сырым. Подготовку, удаление костей/семян, порции и пригодность определяет диетолог. Калорийность источника не переименовывается в измеренную обменную энергию для животных.
- Берётся только первая колонка количества на 100 г съедобной части. Нормы для взрослого человека и проценты не импортируются. Сохраняется точность, опубликованная в таблице; скрытая дополнительная точность источника не предполагается.
- Медь и йод переводятся из мкг в мг, омега-3/6 из г в мг. Остальные единицы сохраняются или проверяются перед вставкой.
- `A_RE` (ретиноловый эквивалент), `Retinol`, `Carotene`, `D` и `D3_MCG` хранятся отдельно от прежних `A`/`D3` в МЕ. Не используем неподтверждённые пересчёты в ветеринарные нормы. `Fiber` (пищевые волокна) не подменяет `CFi` (сырую клетчатку).
- Отсутствующая строка не становится достоверным нулём в БД. В рационе и Excel выводится 0 с признаком неполноты, если данных нет; при частичной заполненности — известная сумма с тем же предупреждением. Для неполных данных статус «в диапазоне» не выставляется. Обязательные колонки исходного калькулятора (включая влагу, клетчатку, золу, A/D/E, таурин и каротин) остаются видимыми.
- Суммирование общих и личных нутриентов идёт по паре код/единица, не по внутреннему ID; разные единицы не смешиваются.

## Воспроизводимость

Первоначальные таблицы получены 30.10.2026 через веб-извлечение: прямые HTTPS-запросы из рабочей среды завершались тайм-аутом. В снимке оставлены только названия строк, числовые факты и категории; тексты статей и человеческие нормы не сохраняются. `fetch.mjs` поддерживает прямую загрузку HTML, ограничение частоты, тайм-ауты и повторы. Его HTML-парсер проверен на тестовом HTML; прямую загрузку всех страниц в этой среде подтвердить не удалось.

Проверить сохранённые данные и пересобрать SQL без сети:

```sh
npm run test:catalog
node backend/database/prisma/catalog/health-diet/generate.mjs --report
node backend/database/prisma/catalog/health-diet/generate.mjs > /tmp/health-diet.sql
cmp /tmp/health-diet.sql backend/database/prisma/migrations/20261030091000_health_diet_catalog/migration.sql
```

Обновить снимок из сети, когда источник доступен:

```sh
node backend/database/prisma/catalog/health-diet/fetch.mjs > /tmp/health-diet-snapshot.json
```

Только после успешной проверки результата заменить `snapshot.json` и подготовить **новую** миграцию. Уже применённую миграцию не редактировать. Генератор рассчитан на добавление новых записей, не на перезапись исправлений администратора: конфликты продукта/значения пропускаются. Изменение существующего состава требует отдельной проверенной миграции. Источник URL и SHA-256 снимка выводятся в отчёте; текущий хеш: `b455a67f6663c00f8a4840314d0361b187284a0d69f82b89b9fc1c0d31bdb358`.

Перед массовым расширением/коммерческим переиспользованием отдельно проверить условия источника. При недоступности сайта миграция продолжает работать с сохранёнными данными; парсер не обходит авторизацию и ограничения доступа.
